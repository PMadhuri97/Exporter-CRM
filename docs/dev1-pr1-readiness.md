## 3. Security — what changed

Every finding from the original audit is closed, **server-side**. None relies on
the UI hiding anything.

| Finding | Before | After |
|---|---|---|
| Notification routes | **No auth dependency at all** — anyone on the network could list and dispatch the queue | `OPERATIONS`/`COMPLIANCE`/`ADMIN` |
| Seven login-only routes | Any account, including a fresh sign-up, could read the platform audit trail and start settlement workflows | Role-gated (3 audit, 2 compliance, 2 workflows) |
| Forged approver | A caller sending `source="SYSTEM"` had its own identity erased from its own approval | Refused at the schema boundary **and** in the service; the actor is always recorded |
| PAN existence oracle | `DEVELOPER` could confirm which company held a PAN through an exact-match filter, masking notwithstanding | 403 naming the parameter |
| Tax-ID reveal | An ownership exception would have switched PII visibility on for a whole role the moment anything populated `relationship_manager_user_id` | `COMPLIANCE`/`ADMIN` only; proven with that column populated |

No role may grant itself more: 27 CRM routes, none admits `API_USER`, and that
is now asserted as an invariant rather than left as a property of today's
table.

### The gate that makes it durable

`backend/tests/contract/test_route_authorization_coverage.py` classifies every
mounted route as gated, public, or signature-authenticated: **49 mounted, 49
classified.** A new route with no classification fails the build, and so does a
row left behind for a route that no longer exists. That is the difference
between "these routes happen to be gated today" and "an ungated route cannot
ship".

## 4. Generated artifacts are committed

`frontend/openapi.json` and `frontend/src/lib/api/schema.ts` used to be
git-ignored, on the reasoning that a copy never committed cannot go stale. The
cost was worse than the risk: `src/lib/api/types.ts` imports the generated
schema, so **a fresh clone could not type-check or build the frontend at all**
without standing up a Python virtualenv and running the backend.

They are committed now, and staleness is caught rather than avoided:
`backend/tests/contract/test_openapi_artifact_is_current.py` regenerates the
document and fails if the committed copy differs, naming the added or removed
routes.

`build`, `typecheck`, `test` and `lint` reference no Python. Only
`generate:api:schema` does, and it is maintainer-only.

## 5. What this PR deliberately does not do

**Server-served allowed moves.** Section 7.5 requires the server to serve the
allowed journey, gauge and deal moves, and the frontend to fetch them.
`frontend/src/modules/onboarding/constants.ts:103-139` still hand-copies the
backend's transition table. **This is the one place the target architecture
remains violated in code.**

It was not built because ownership is unassigned: it appears in no task list
L1-01 to L1-15, and the endpoint must cover the journey (Dev2), qualification
(Dev2), conversation (Dev3), background check (Dev4), deals (Dev3) and the
calling user's permissions. Building it as Dev1 would absorb three other
developers' contract surface.

**The risk of leaving it unowned is not neutral:** each gauge owner needs the
same table. With no owner when they start, the likely outcome is four
hand-copied tables instead of one.

**No Dev2/3/4 business features.** No company, deal, buyer or gauge model was
created — not even to make a Dev1 test pass. `DealsPanel` renders `null` and
`HistoryService.list_for_deal` returns an empty page precisely so that none was
needed.

Three Dev2-owned files *were* touched, each mandated by a Dev1 task (L1-10
tax-ID visibility, L1-11 the shared writer). The journey transition table, the
compliance gate, the routes and the entities in them are byte-identical to
`main`.
